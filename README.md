# 软包挤挤站 · 测试版开发仓库

一款中文、轻量、单机的装箱解谜游戏。玩家把不同形状的包裹放进格子箱子，旋转、挪动，并把一只特别的软包「挤一挤」或「松一松」，直到所有可用格子刚好装满。

## 当前状态

本项目已实现 Canvas2D 可玩 Demo 代码，尚未公开发布、上传抖音测试版或通过平台审核。独立私有 GitHub 仓库已建立，源码修改由指定同步流程备份。

已实现：
- 全部玩法、包裹、棋盘、选关、说明、参考拼法和操作按钮由 Canvas2D 绘制，不依赖 DOM 游戏控件。
- 点击放置和指针拖动、旋转、软包压缩/展开、取出、撤回、确认重置、通关与下一关。
- 10 个手工关卡，版本化本地存档、损坏/禁用存储降级、音效开关、原创代码生成的短音效。
- 共享的 browser 与 `tt` 适配器；平台对象注入画布、尺寸、输入、存储、音频、帧与生命周期。
- 自包含浏览器 Demo：`dist/parcel-demo.html`；抖音候选导入目录：`dist/douyin/`（AppID 留空）。

已验证：
- 72/72 Node 自动化测试通过，10/10 关卡参考解通过。
- 规则测试含 2,500 次确定性混合操作不变量检查。
- 真实 `startGame(platform)` 在三种逻辑视口的模拟平台中，通过全部 10 关的 Canvas 指针点击流程；另测拖放/取消、错误放置、取出/撤回/重置、存档与生命周期。
- 最终生成的 `dist/douyin/game.js` 在无 DOM 的 `tt` VM 模拟环境中启动，并通过真实入口的指针输入完成第 1 关。

尚未验证：
- 真实浏览器画面与输入 QA、真手机测试、抖音开发者工具编译及真机运行。当前云执行环境与浏览器的 localhost 路线不通，无头浏览器启动也被环境限制；不能把模拟平台测试称为浏览器或真机通过。
- 抖音账号/AppID、平台配置、侧边栏复访要求、审核素材、测试版上传与分发仍需在正式平台流程中验证和完成。当前没有正式平台发布许可结果。
- 微信适配器尚未实现；目前只是预留同一平台接口，不能宣称微信版本已兼容。

测试证据：`artifacts/test-output.txt`、`artifacts/level-verification.txt`。已修复第一教学关意外依赖旋转，以及「L 形左上角为空时点击锚点误选邻包」的交互缺陷。

## 核心玩法与差异点

- 普通包裹只能旋转，不可翻面。
- 第 5 关开始出现一只粉色软包。展开时为 2×2 的 4 格方形，压缩后为 3 格 L 形；两种形态都可以旋转。
- 某些关卡需要压缩，另一些关卡需要展开。目标始终是「全部包裹放入，同时填满每一个非隔板格子」，不是简单地把小包堆进去。
- 压缩是离散状态切换，不模拟物理变形；界面会清楚标明当前状态与占格数。
- 无倒计时、体力、抽卡、账号或广告，适合先测试解谜是否有趣。

## 测试版目标范围

1. 手机触摸与桌面鼠标均可操作，可点击选择并放置，也可拖动。
2. 旋转、软包压缩/展开、取出、撤回、重置。
3. 10 个经规则引擎验证可解的手工关卡，前期逐步教学，后期增加空间与件数。
4. 选关、通关记录、当前进度的版本化 localStorage 存档；浏览器拒绝存储时仍能游玩。
5. 本地合成音效与开关，不下载或购买外部素材。
6. 规则测试、存档异常测试、手机及桌面浏览器流程测试。

## 运行与验证

需要 Node.js 20 或更新版本，无需安装第三方依赖。

```sh
npm test
npm run verify
npm run build
npm start
```

- `npm test`：72 个规则、存档、运行时与最终构建测试；其中包含模拟平台流程，不是浏览器自动化。
- `npm run verify`：逐关执行全部参考解。
- `npm run build`：生成单文件浏览器 Demo 与抖音候选导入目录。
- `npm start`：本机静态服务器，默认 `http://127.0.0.1:4171`。可用 `PORT=4183 npm start` 改端口。服务是否能被其他执行环境访问需单独确认。
- `dist/parcel-demo.html` 自包含所有源码和短音效，可作为私人离线试玩文件打开，不必拉取外部资源；浏览器对 `file://` 存储行为各异，存储受限时游戏会提示并继续运行。
- 源码入口 `index.html` 使用 ES Modules，请通过静态服务器访问，不要直接双击该源码入口。
- 仅在受信任局域网且由项目负责人明确安排设备测试时，才考虑 `HOST=0.0.0.0 npm start`；不要默认扩大可访问范围。

## 引擎与平台边界

当前 Demo 使用原生 Canvas2D 和 JavaScript，不是 Cocos Creator 或 Unity 项目。游戏逻辑与渲染通过 `startGame(platform)` 和平台宿主隔离，便于先跑通抖音，再做微信适配；这降低移植成本，但不会自动产生跨平台验证结果。

构建器只处理本项目明确列出的已审查模块图，会拒绝改变的 import/export 结构，并用最终包的 VM 测试检测绑定冲突。它不是通用 bundler，也不转译现代 JavaScript 语法。正式工程扩展时应采用经过验证且锁定版本的工具链，并由抖音开发者工具重新验证。

`dist/douyin/project.config.json` 的 AppID 故意留空。`tt` Canvas、触摸、同步存储、音频和前后台生命周期适配器只有模拟测试，不能把该目录称为已上传、已编译、已审核或可供公众访问的抖音小游戏。平台要求的侧边栏复访等流程尚需实现/验证后才能上传。没有平台登录、广告、支付、排行榜、云存储或微信 `wx` 适配器。

存档只保存在当前设备/站点的本地存储，不是云备份；清理浏览器数据或换设备可能丢失。当前保存摆放、方向、压缩状态、步数和通关记录，不跨重新打开保留撤回历史。源码 GitHub 备份与玩家存档是两回事。

Demo 优先手机竖屏和桌面鼠标；Canvas 控件目前没有完整键盘和屏幕阅读器导航。尚无真手机性能基准、低端机兼容结论、PWA 安装或跨设备存档。

## 源码备份与发布约定

- 每款游戏使用独立、非公开的 GitHub 仓库。
- 先建立私有仓库并提交说明，再继续开发。
- 每个可检查的实现、修改与修复都应形成提交并同步到对应私有仓库，检查远端状态后才宣称同步完成。
- 不在仓库保存账号口令、令牌、密钥或个人资料。
- 测试版开发不等于公开发布。未经项目负责人明确同意，不创建公开站点、不发布平台版本、不把私有源码改成公开。

## 责任分工

开发侧负责规则、缺陷修复、自动化与流程测试，并如实记录未验证项目；项目负责人负责实际游玩感受、关卡难度和创意建议。任何自动化通过均不替代真人试玩。
