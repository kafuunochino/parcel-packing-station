# 软包挤挤站 · 测试版开发仓库

一款中文、轻量、单机的装箱解谜游戏。玩家把不同形状的包裹放进格子箱子，旋转、挪动，并把一只特别的软包「挤一挤」或「松一松」，直到所有可用格子刚好装满。

## 当前状态

本项目处于浏览器原型开发阶段，尚未正式发布，也不是已接入抖音或微信的小程序包。

已经准备：
- 无第三方依赖的纯规则模块：边界、碰撞、旋转、软包形态切换、取出、撤回、重新开始、通关判定。
- 10 个手工设计关卡，以及可执行的参考解验证。
- 版本化本地存档模块及本地静态服务器脚本。

待完成：
- 可玩的 HTML/CSS/JS 界面、移动端触摸与桌面鼠标交互。
- 教学、选关、音效开关、通关反馈。
- 自动化单元测试及浏览器流程测试。

开发已按项目负责人要求暂停，等待先建立独立私有 GitHub 仓库并保存此说明，再继续实现。

## 核心玩法与差异点

- 普通包裹只能旋转，不可翻面。
- 第 5 关开始出现一只粉色软包。展开时为 2×2 的 4 格方形，压缩后为 3 格 L 形；两种形态都可以旋转。
- 某些关卡需要压缩，另一些关卡需要展开。目标始终是「全部包裹放入，同时填满每一个非隔板格子」，不是简单地把小包堆进去。
- 压缩是离散状态切换，不模拟物理变形；界面会清楚标明当前状态与占格数。
- 无倒计时、体力、抽卡、账号或广告，适合先测试解谜是否有趣。

## 测试版目标范围

1. 手机触摸与桌面鼠标均可操作，可点击选择并放置，也可拖动。
2. 旋转、软包压缩/展开、取出、撤回、重置。
3. 10 个经规则引擎验证可解的手工关卡，前期逐步教学，后期增加空间与件数。
4. 选关、通关记录、当前进度的版本化 localStorage 存档；浏览器拒绝存储时仍能游玩。
5. 本地合成音效与开关，不下载或购买外部素材。
6. 规则测试、存档异常测试、手机及桌面浏览器流程测试。

## 运行与验证

需要 Node.js 20 或更新版本，无需安装任何第三方包。

```sh
npm run verify
npm test
npm start
```

- `npm run verify`：逐关执行参考解，确认 10 个关卡可解。
- `npm test`：运行 Node 内置测试框架（测试用例待实现）。
- `npm start`：默认监听 `http://127.0.0.1:4173`。游戏界面完成前，这个地址不会显示可玩游戏。
- 可使用 `PORT=4183 npm start` 调整端口。
- 仅在受信任局域网且由项目负责人明确安排设备测试时，才考虑 `HOST=0.0.0.0 npm start`。这会扩大可访问范围，不应默认启用。
- 不要直接双击 HTML 文件运行 ES Modules，请通过静态服务器访问。

## 文件结构

```text
src/rules.js               纯规则与状态转换
src/levels.js              10 个手工关卡和参考解
src/storage.js             版本化本地存档、异常降级
scripts/serve.mjs          无依赖本地静态服务器
scripts/verify-levels.mjs  执行全部关卡参考解
TEST_PLAN.md              自动化和试玩验收清单
```

## 浏览器原型与抖音 / 微信版本的边界

本仓库首先验证玩法和可用性，不把普通网页称为已完成的小游戏平台版本。

目前没有抖音或微信小游戏 SDK、平台登录、云存储、广告、支付、分享奖励、平台榜单、审核素材或平台构建产物。DOM/CSS 界面不能直接视为可发布的小程序包；接入时需要根据所选平台的当前工具链、渲染环境、输入事件、生命周期、存储和音频机制做适配，并重新测试。

没有做真实手机型号覆盖、性能基准、断网安装/PWA 或离线缓存保证。`localStorage` 仅保存在当前浏览器与当前站点来源中，不是云备份；清理浏览器数据或换设备可能丢失进度。源码的 GitHub 备份与玩家存档是两回事。

## 源码备份与发布约定

- 每款游戏使用独立、非公开的 GitHub 仓库。
- 先建立私有仓库并提交说明，再继续开发。
- 每个可检查的实现、修改与修复都应形成提交并同步到对应私有仓库，检查远端状态后才宣称同步完成。
- 不在仓库保存账号口令、令牌、密钥或个人资料。
- 测试版开发不等于公开发布。未经项目负责人明确同意，不创建公开站点、不发布平台版本、不把私有源码改成公开。
